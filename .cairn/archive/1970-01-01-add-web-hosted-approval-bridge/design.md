## Architecture

The composition lives in kiln-hosted, which already depends on kiln-web-service; Web must not import hosted implementations. A kiln-web-hosted binary opens the existing Web HTTPS server with explicit per-project hosted WorkflowPort adapters. Existing Web/Lattice construction remains the default. Provider-neutral WorkflowDispatchBinding carries run ID, project ID, SourceResolution and optional UntrustedGate from the persisted record on dispatch and recovery.

The Web project explicitly selects `execution_provider = hosted`; the default Lattice selection is omitted for existing profile identity compatibility. Selection belongs to the canonical persisted service profile, not only a runtime factory option, so a provider switch cannot silently reuse existing Web state. Hosted capabilities and execution references use the hosted namespace; they never masquerade as Lattice. The default Web binary rejects hosted selection before binding/effects and points operators to the explicit composition.

## Authority and source

The host operator pins each dedicated Web Iroh peer to an organization, Web project/repository identity, hosted project, reviewed pipeline, price and class. Only that current authenticated peer with current project authority may call execution.web_run for the policy. It vouches for the Web interactive approval decision, not an arbitrary approver string from an ordinary hosted member. Hosted validates the complete gate, exact commit and plan binding; independently acquires the commit from its operator-enrolled local Git repository and verifies canonical-tree identity. It materializes only those exact bounded canonical bytes into a private deterministic workspace and uses that source for execution. There is no caller-selected workspace or source tree in this route. This does not fix the upstream Radicle transport authentication disclosure or convert caller provenance in ordinary execution.run into verified approval.

## Durability and lifecycle

Bind the complete request, policy/issuer, Web run and hosted attempt durably before an execution effect. Repeated identical input returns or recovers the original attempt; changed input for a Web run/attempt conflicts and cannot create a second attempt. execution.web_get never creates a workspace or starts a job. The Web service preserves reserve-before-dispatch and unknown-outcome recovery; the adapter must never retry an uncertain dispatch as a new run. Map real hosted node outcomes, receipts and retained logs without synthetic successes. Pause/resume and unsupported graph mappings fail before effects; cancellation remains exact-attempt-bound. Membership, incident holds, resource, runner and host-safety gates stay in force.

Dispatch must not hold the Web engine lock for a guest's lifetime. The adapter starts one owned background RPC and returns explicitly unverified Unknown without receipt/logs; one endpoint multiplexes bounded execution and observation/control requests. Only current durable observations advance state. Reserved bindings with no execution row remain Unknown with their actual stored verification flags, including after a crash, and can never redispatch. A present execution row must match the reserved exact request/configuration identity and both verification facts; the globally reserved Web attempt/source namespace survives policy removal. A cancellation request does not imply Cancelled until the actual hosted outcome and teardown prove it.

The current consumer is Web's asynchronous hosted port: an admitted same-execution, monotonic Running/Paused observation must reconcile canonical Unknown back to Pending before cancellation becomes available. The pure core admits that nonterminal reconciliation only with an exact live reference, matching any retained reference; decision and replay reject missing/substituted references. It emits no dispatch effect and retains the original attempt identity. Existing terminal reconciliation, serialized commands/events and default provider selection are unchanged.

## Verification and limits

Use real local HTTPS Web approval and authenticated loopback Iroh hosted calls, exact native Git source and durable state. Exercise missing/stale/superseded approval, unauthorized issuer, moved/altered source, same-run replay, restart recovery and changed-input conflict. Local kernel is below the retained untrusted preflight threshold: correct handoff may end at explicit host refusal; do not waive it or describe local admission as successful VM execution. Full untrusted VM qualification requires a separate eligible-host allocation. No private keys, bearer tokens or raw hosted database are public evidence.
