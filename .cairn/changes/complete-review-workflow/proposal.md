## Why

The current interactive review loop requires manually registered local commits, global reviewer policy and manual fast-forward submission. Kiln dashboard users need ownership enforcement, contribution intake, daily review ergonomics, delivered attention and queued CI-bound integration.

## What Changes

- Add path/team ownership requirements, automatic reviewer requests and explicit target-write enforcement boundaries.
- Add authenticated source contribution intake that creates or updates stable reviews from submitted branches and exact commits.
- Add syntax highlighting, safe Markdown, whitespace comparison and revision-bound applyable suggestions.
- Add mentions, subscriptions and durable externally delivered review notifications.
- Add exact integration candidates, canonical CI evaluation and a restart-recoverable merge queue.
- Qualify successful required CI through approval and submission, including negative and restart paths.

## Impact

- **Consumer/outcome:** Kiln dashboard developers can contribute, review and integrate code without manually stitching these workflows together.
- **Owner:** Kiln maintainers own core semantics, provider conformance and service/browser integration; operators own deployment, target-writer access and recipient configuration.
- **Adoption:** Explicit typed Nickel profiles admit local providers, source mappings, delivery endpoints and automation authority. Existing review callers migrate cleanly.
- **Verification:** Disposable Git repositories, real canonical CI execution, isolated notification receivers, authenticated HTTPS/browser and repository gates provide repeatability evidence.
- **Non-claims:** No real remote publication, real target mutation, production deployment, real recipient delivery, signing or lifecycle release authority is granted.
