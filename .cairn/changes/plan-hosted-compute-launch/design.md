## Context

Kiln has a locally qualified single-tenant CI workspace, authenticated workers and bounded measurements. Its independent GitHub adapter already admits remote push/PR events, acquires exact source through reviewed jobs and publishes commit status, with historical separate-worker evidence. The web service's local-checkout enrollment is not that remote adapter's customer onboarding. Kiln does not have commercial billing or hostile-customer isolation evidence. Animus has bounded model clients; spark-nixos records actual GB10/Docker inference but does not qualify a paid gateway. The user chose open-source software with paid hosted CI and inference, launch planning first, and clarified that source stays on remote hosts.

## Goals and Success Contract

Publish one concrete, source-linked plan that separates existing facts, recommendations, unmade operator decisions and future launch evidence. Both paid products must have metering, failure, cost, safety and go/no-go criteria. Completion means a checked plan, not an enabled paid service or company formation.

## Decisions

### Decision: Sell operated compute, not permission to use Kiln

**Choice:** Preserve existing software licenses and self-hosted functionality. Recommend an invite-only B2B pilot with separately enabled runner and inference SKUs, explicit spend limits and operator-reviewed hosted invoices. No per-seat license gate, prepaid wallet, marketplace or unlimited-compute offer.

**Rationale:** This matches the selected business model and bounds financial and operational exposure before public self-service.

### Decision: Financial authority outside CI core

**Choice:** Plan a hosted-service composition with durable usage/reservation/invoice journals and versioned payment/executor/provider ports. Kiln retains CI semantics; model clients and infrastructure keep their owners. Existing timing, token and budget observations require explicit commercial admission, not relabeling as invoices. Do not extract a shared billing library or add mutable sibling dependencies during planning.

**Rationale:** CI outcomes, provider observations, invoice creation and settled payments are distinct authority domains. A successful redirect or asynchronous meter acknowledgement is not payment or spend authority.

### Decision: Connect remote source; host CI, not repositories

**Choice:** Preserve the customer's source host, repository permissions and merge authority. Recommend the existing GitHub connector for an operator-assisted pilot with dedicated control/data deployments per organization; keep Radicle as an independent existing adapter, not a migration requirement. Define organization/project/connection identities, stable native repository binding, scoped credentials, reviewed exact-source workflow routing and generation-bound revocation. No repository creation, push service, authoritative mirror or replacement forge is proposed. Source snapshots/caches remain private CI inputs with explicit retention.

**Rationale:** This matches the user's product boundary and reuses qualified remote-source mechanisms. A local-checkout registry or source-browsing UI cannot stand in for remote connection onboarding. The next runtime change must own its specification and prove the full connection → event → exact checkout → execution → visible result/status path, including negative/recovery cases. This planning change neither implements it nor grants source-host or live financial mutation authority.

### Decision: No-spec planning classification

**Choice:** Use `no-spec-delta` and change-local acceptance. Change only this package, the commercial planning document and its README link. Hash-bind the plan classification inputs and record an explicitly agentic self-review; it is not independent, legal or release approval.

**Rationale:** Recommendations and open launch gates do not amend accepted software behavior. Future product implementation needs separate lifecycle work rather than treating this plan as production policy.

## Risks / Trade-offs

- Dedicated customer environments cost more than shared workers; shared hostile execution is not currently qualified.
- Postpaid invoicing carries bounded credit risk; reservations and customer limits must precede billable effects.
- Model serving and provider clients are not a complete inference business; commercial rights, usage reconciliation, cancellation and cost remain release gates.
- Prices and company jurisdiction cannot be invented from source. Keep these explicit operator decisions, not implied approvals or sample live values.
- Existing release-readiness holds remain unchanged. Passing document gates is not permission to deploy, charge, publish or archive.
