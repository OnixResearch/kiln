## Why

The operator requests a more minimal, useful live UI and deployment afterward. Oversized counters, repeated framing and sixteen first-level destinations consume attention before an operator reaches a failed execution.

## What Changes

- Remove decorative workspace chrome and hard shadows; retain readable light/dark/system appearance, density and mobile focus/touch targets.
- Present retained counts in a compact status strip and latest project executions in a failure-first list with direct pipeline/log links; keep timing observations behind a disclosure.
- Collapse secondary work/inspection destinations and advanced run filters without removing routes, permissions or exact control confirmations.
- Deploy the checked candidate to the existing desktop service, preserving credentials, profiles, work records and CI history.

## Impact

Current consumer: authenticated Kiln developers and CI operators. Maintenance owner: Kiln web-service/dashboard maintainers; the operator owns deployment. Durable capability: a scan-first execution overview and progressive disclosure over existing workflows. Changes remain in live HTML/JS/CSS and operator documentation; no API, backend, offline catalog or authority change. Verify real retained data, failure filtering, direct logs, disclosures, keyboard/mobile interaction, package checks and the actual deployed surface. Existing lifecycle/release holds remain explicit.
