# Design: one Radicle source-to-build-to-status composition

## Decisions

Keep provider implementations outside core crates. The new imperative composition shell owns files, durable reservation, the existing Aspen transport and the dedicated status shell. Existing pure CI decisions/replay, trigger parsing/identity, source proof verification, Nix task composition and status classification remain authoritative. Do not convert a broker event into a fabricated signed operator request or make the operator pilot accept unsigned input.

The first admitted event is a push for one configured repository and branch. Unsupported patch/event shapes fail before external effects. Source policy fixes the local repository path, RID, signer namespace, branch and snapshot bounds. For each new candidate the source shell captures the current signed-refs identity once, binds the event revision, verifies the existing complete source contract, and freezes/materializes only admitted regular/executable files. Stale references, unsafe paths, symlinks, gitlinks and content/bound drift fail closed. A reserved candidate does not follow a moved branch during recovery.

A static reviewed project-worker profile fixes source policy, evaluator/build cohorts, selector, selected task and bounded private state. The mapped Lattice command and its profile identity stay unchanged across revisions. The worker derives candidate-local identities from that profile and exact source context, persists its acquired-source and resolved-job facts, imports the acquired bytes into the Nix store through the measured bounded executable, and reuses the existing discovery/build/root-release path. Neither a separately supplied consumer snapshot nor edited acquired source may replace the event source. Provider-native Git and Nix algorithms remain native; Kiln-owned identities use BLAKE3.

Canonical run/attempt identity and native ingress are derived deterministically from the admitted broker trigger. The controller persists StartRun and ingress before submission. A duplicate loads the existing reservation. Recovery uses native reconciliation of the original operation; an interrupted or ambiguous submission never authorizes a fresh dispatch. Completion requires exact linked native terminal and actual source/worker evidence, admitted discovered task/build plan and canonical outcome. Pending/unknown observations cannot become success or final status.

Status remains a separate capability. The versioned status plan/action/observation binds RID, exact source revision, run, idempotency key and outcome. All current callers/configuration move to that contract; historical evidence remains historical, and incompatible older COB actions fail closed rather than receiving an invented revision. Canonical terminal state determines the projection. Persist the exact publication intent before calling the signer/store; an interrupted or unknown write uses read reconciliation and retains uncertainty if no exact result exists. Do not add implicit remote synchronization.

## Parallel implementation contracts

- Source slice: extend only the Radicle source shell/module and source-native regressions with `RadicleSourceSelection` (fixed repository_path, repository_id, signer_node_id, signed_reference, profile_id and SnapshotLimits), one-shot exact request capture, and bounded materialization returning the admitted source result. Expose clear serializable receipt/result types. Do not change trigger or status authority.
- Status slice: migrate the dedicated status profile/plan/COB action/write observation and every current caller to mandatory exact source revision; include revision in idempotency/reconciliation checks. Own only status-related files, configuration and regressions; do not edit historical archives.
- Worker slice: own project profile/result/bindings in the new composition package's `project` module plus project run/release entrypoints in the existing worker. Coordinate the source API directly with the source slice. Reuse the actual worker/adapters and retain immutable source evidence; no provider mock/fallback.
- Parent: integrate the new composition package, canonical journal/status outbox, broker protocol entrypoint, typed controller configuration, packaging, actual producer/runtime proof and lifecycle closeout. Root manifests and shared integration files have one owner.

All workers skip build, tests, lint and formatting while editing. The integration owner runs focused behavior and required gates after the slices integrate. Pure admission/regression tests do not start an external service; actual service/producer execution is a separate bounded smoke rail.

## Verification and authority

Use existing checked-in successful workspace/Nix receipts as the pre-change baseline; do not rerun the known shared-cache permission failure. Host Cargo commands use a private target directory. Exercise malformed/wrong repository/branch/revision, moved sigrefs, unsafe trees, unknown native outcomes, result substitution, publication uncertainty and conflicting status revisions alongside positive cases. Run actual producer and maintained host/Lattice/Nix success/failure with duplicate delivery and restart, preserving exact source, original invocation, rooted handoff/release and status evidence. Retire private processes and credentials. Any unreachable genuine producer or operator-authority prerequisite stays an explicit unmet criterion; fixtures alone are not live qualification.
