## Why

Current source publication retains three unqualified Aspen-host production-evidence obligations. Historical host checks belong to older exact cohorts; checked task lists and source publication cannot refresh them. The current consumer is Kiln's bounded Aspen/Lattice CI host, maintained by Kiln maintainers for an authorized local operator.

## What Changes

- Inventory existing receipts against source, executable, profile, provider and publication identities; reuse only evidence whose scope still matches. a[qualify-aspen-host-production-evidence.cohort]
- Exercise the missing isolated real-process restart, corruption, provider teardown, finite-load, backup/restore, rollback and authority cases with named finite bounds. a[qualify-aspen-host-production-evidence.execution]
- Admit a complete exact-cohort qualification receipt and reject missing, failed, mixed or stale evidence and claims stronger than bounded local host behavior. a[qualify-aspen-host-production-evidence.admission]
- Retain current command results and artifact identities; close traceability only through the corresponding implementation and executable verification, without changing accepted requirement bodies or weakening policy.

## Impact

- **Files**: standalone host qualification core/shell and native fixtures, applicable Nix checks, operator documentation and this change's source-bound evidence.
- **Testing**: baseline native host/provider checks; positive and negative receipt admission; actual host/extension/provider process scenarios; all-target/all-feature tests, strict Clippy, Octet deny-all, required root/Nix checks and native Cairn validation/gates/traceability.
- **Owner and adoption**: Kiln maintainers own the repeatable local qualification rail and operator receipt review for the existing host. This does not add a second CI execution path.
- **Out of scope**: live production disruption, remote publication/signing/governance, unrelated active changes, new provider implementations, global durability, exactly-once delivery, CI/provider correctness, sandboxing or automatic deployment/release authority.
