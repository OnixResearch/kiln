# Lattice agent orchestration

Kiln submits agent review jobs to Lattice. Lattice runs them. Kiln keeps review policy and evidence.

## Boundary

| Owner | Responsibility |
|---|---|
| Kiln | Which job is admissible, the budget ceiling, the permission ceiling, advisory or binding vote policy, Patchgate receipts, untrusted-PR holds, journals, and billing |
| Lattice | The agent runtime, the reviewed route, execution budgets, approvals, and the check that an agent cannot widen its access |

The pure planner is `kiln-core`'s `plan_lattice_agent_job`. It emits one workflow node:

- kind `agent`
- effect class `custom`
- adapter kind `agent`
- controls cancel only

`config/lattice-agent-profile.ncl` is the matching cohort. CI keeps `config/lattice-workflow-profile.ncl` and does not admit `agent` nodes.

The operation identity is BLAKE3 over the harness (`pi`, `clankers`, or `animus`), optional declared model, prompt identity, vote policy, budget, and sorted permissions. Changing any of those is a new graph. The Lattice route must bind that graph. Kiln does not store the prompt body or select a model endpoint.

Permissions must include `agent/execute` and may include only `read/candidate` and `write/review-note`. Anything else fails before a request exists.

Budgets above 1 invocation, 32,768 tokens, or 900,000 ms fail the same way. Those ceilings match Lattice's guarded per-round bounds. Lattice still enforces the budget on the reviewed route.

## Evidence

`admit_agent_run_evidence` accepts a Lattice observation only when it matches the admitted plan. A completed run sets `process_succeeded`. `counts_as_approval` and `is_patchgate_receipt` stay false, including when Kiln policy says agent votes are binding. A binding vote still requires Kiln's attested submission path. Patchgate stays on the Patchgate adapter.

## Handler

Dispatch uses the existing Unix exchange and handler revision `85a38b6a4bceeae4bb2057cf157e21752100f1b5`. The decision record is [the Lattice boundary ADR](adr/lattice-runtime-and-agent-orchestration.md).

This slice does not start Lattice, does not vendor the Lattice application, and does not prove a live agent route. Operators review a route whose concrete workflow is an agent node with the same operation identity. Until Lattice publishes that route shape, the binding is operator-reviewed rather than generated by Kiln.
